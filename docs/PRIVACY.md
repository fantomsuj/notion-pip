# Perch Privacy Policy

_Effective August 25, 2026_

Perch is a small macOS app that displays the real Notion website in a native floating panel. Perch does not operate a cloud service, sell personal information, or include advertising or third-party analytics.

## What Perch handles

- **Your Notion session and page content:** Workspace search, editing, and page creation happen inside Notion's embedded web interface. Sign-in begins there and may continue in a secure system-browser authentication session when Notion requires it. Perch never asks you to enter a Notion password into native app UI and does not use a personal integration token. Authentication returns website cookies to WebKit's persistent website data store on this Mac so the embedded Notion session can survive relaunches. Notion receives authentication and page data under [Notion's privacy policy](https://www.notion.so/privacy).
- **Local page state:** Perch stores validated Notion page URLs and IDs, page titles, device-local pin roles, recent-page history, and best-effort restoration state such as scroll position under the current macOS user's Application Support data. Optional beta custom pinned URLs, panel geometry, size presets, onboarding state, shortcut settings, and menu-bar preferences use the user's macOS Preferences. The Notion session and other website data use WebKit's website-data storage. These local stores remain on this Mac unless the user backs up or syncs their Library through another service.
- **Local store recovery:** If Perch cannot open its local page-state store, it can continue for that session without saving or, after explicit confirmation, move only `Perch.store` and its named SwiftData companion artifacts into a dated folder under `Application Support/com.fantomsuj.Perch/Recovery`. Recovery is a reversible local move, not a deletion or upload. It does not move Preferences, WebKit website data, Notion cookies, the application instance lock, or Notion account data. The archived raw store can still contain private page URLs, titles, roles, and restoration state and remains on the Mac until the user deliberately removes it.
- **Diagnostics:** Perch uses Apple's local unified logging and performance signposts. Private page identifiers are marked private where logged. Perch does not transmit its own diagnostics or telemetry to the developer.
- **Context Suggestions:** This optional feature uses macOS Accessibility access in two narrow ways. Its existing saved-page suggestions read the frontmost application's name and bundle identifier, focused window title, and an exposed document URL, then compare that transient context on-device with the titles and device-local roles of at most seven pinned and seven recent pages. A user-initiated Perch reveal performs one separate exact-page check. That check reads only focused `AXDocument` or `AXURL` attributes on the focused window, focused element, and at most three parents. It does not use a window title to infer a page. Browser values must pass Perch's strict HTTPS Notion page validator; only the native Notion bundle may normalize a `notion://www.notion.so/...` deep link before the same validation. Raw Accessibility application, title, and URL candidates—including rejected candidates—are not saved, logged, uploaded, inserted into Notion, or copied to the clipboard; pending reveal and dismissal state is memory-only. If Perch auto-opens a validated page, or the user chooses **Open Here**, that page URL, identifier, title, recent-page entry, and restoration state follow the ordinary device-local page-state behavior described above.
- **System permissions:** Perch requests Accessibility access only after the user enables Context Suggestions. Disabling the setting stops that monitor immediately. Perch does not request screen-recording, microphone, camera, Contacts, or location access. Website features presented by Notion remain subject to Notion's behavior and macOS permission controls. Launch at Login is changed only when the user operates its Settings toggle.
- **Local agent streaming:** Off by default. When you enable Settings → Local Agents → Allow local agents, Perch opens a loopback-only HTTP listener and publishes a short-lived discovery file at `~/Library/Application Support/com.fantomsuj.Perch/agent-server.json` with owner-only (`0600`) permissions. The file contains a per-launch bearer token, base URL, process id, and start time—not Notion cookies, page bodies, or an integration token. Same-user processes that can read that file can authenticate. Streamed Markdown is retained in memory for the live overlay until you Accept (paste once), Dismiss, cancel, the stream expires, or Perch quits. Ready streams may also show a local notification with Accept and Dismiss actions; notifications summarize readiness and do not include the Markdown body or bearer token. Disabling Allow local agents stops the listener and removes the matching discovery file. See [AGENT_STREAMING.md](AGENT_STREAMING.md).

## Quick Copy

Quick Copy is deferred from Perch 0.1. The app has no Quick Copy control and does not start its Accessibility selection monitor. Context Suggestions reuses its own opt-in monitor and does not read selected text, page contents, or clipboard data.

The source repository retains an isolated experimental implementation for possible future testing. If a later release introduces it, the feature will require a new first-use explanation and an updated policy before release. The prototype observes selected text only while visibly armed, rejects secure fields, keeps accepted text in memory long enough to insert it at the saved Notion cursor, and does not change the clipboard or persist captured text. Accessibility access can be revoked in System Settings → Privacy & Security → Accessibility.

## Retention and deletion

Perch keeps local page and restoration state until it is replaced through normal use or the app's data is removed. A recovery archive is retained separately and is not automatically deleted after Perch creates a fresh empty local store. To remove Perch and its local state, including any Recovery folders, follow [the uninstall instructions](SUPPORT.md#uninstall-perch-and-remove-local-data). Website data for the embedded Notion session is removed with Perch's WebKit data container; signing out in Perch also ends the visible Notion session according to Notion's behavior.

## Support

Questions, privacy requests, and bug reports can be submitted through [Perch's support tracker](https://github.com/fantomsuj/notion-pip/issues/new). Do not include passwords, session cookies, private page content, or other secrets in a report.

Material changes to this policy will be published in this repository with a new effective date.
